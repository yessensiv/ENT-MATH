## Google — выбран, пока не реализован

Владелец выбрал Google как самостоятельный вход без обязательного ChatGPT. Кнопка Google на странице авторизации **ChatGPT** этого требования не выполняет.

Платформа Sites владеет текущими маршрутами входа и заголовками идентичности. Прежде чем добавлять стороннюю авторизацию, нужно подтвердить поддерживаемую интеграцию внешнего провайдера у Sites; такое подтверждение пока не получено. Нельзя подменять `/signin-with-chatgpt`, `/signout-with-chatgpt`, `/callback` или доверять переданному браузером email.

После подтверждения механизма потребуются:

- Google Cloud OAuth Web client, client ID и client secret в серверных секретах, consent screen, страницы политики конфиденциальности и условий.
- Контролируемый домен и подтверждённый HTTPS callback. Предлагаемый **будущий**, пока не работающий путь — `/api/auth/google/callback`; не активируйте интеграцию до реализации и проверки этого обработчика. Системный браузер нужен для входа Google.
- `openid email profile`; идентификация по Google `sub`. Совпадение email не связывает профили и не выдаёт администратора. Привязка выполняется только из уже авторизованного действующего профиля с отдельным подтверждением.
- Проверка `state`, PKCE, nonce, iss/aud/exp; защищённые серверные сессии и отзыв; два реальных аккаунта и тест сохранения истории после привязки.

Первичные источники: [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect), [Web-server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [политики OAuth](https://developers.google.com/identity/protocols/oauth2/policies). Код собственного Google OAuth и сессий пока не выдан за готовую интеграцию.

## Полная резервная копия и проверка

1. Войдите в опубликованный сайт реальным аккаунтом владельца из `ADMIN_EMAILS`. Откройте панель редактора → «Скачать полную резервную копию». `/api/admin/backup` доступен только администратору. Сохраняются 14 таблиц (архив v3; чтение прежних v1/v2 поддерживается) с контрольной суммой. Более 10 000 строк в одной таблице или 24 МБ требует отдельного полного экспорта D1; усечённая копия не считается полной.
2. Положите файл в защищённое хранилище **вне** основной базы/деплоя. В нём профили, решения, переписка и согласия: не публикуйте его в репозитории или общедоступной ссылкой. Настройте права, шифрование и политику 30 дневных/12 месячных копий после согласования бюджета и сроков хранения.
3. Из корня проекта проверьте и восстановите в **новый** файл:

```powershell
node --experimental-strip-types scripts/verify-backup.mjs C:/secure-backups/ent-math.json
node --experimental-strip-types scripts/restore-backup.mjs C:/secure-backups/ent-math.json C:/secure-backups/restore-check.sqlite
```

Вторая команда откажется перезаписывать существующий файл. Она применяет схему из доверенного репозитория, сверяет таблицы, строки, контрольные суммы состояния и `integrity_check`. Для повторного испытания задайте другое новое имя. Указанный каталог — пример: сначала выберите собственное защищённое место.

4. Сверьте профиль, экзамен, учебную историю и публикации в изолированной тестовой среде. Затем отдельно подготовьте импорт в новую D1 и переключение привязки Sites; автоматического импорта этого JSON в production в выпуске нет. Не запускайте произвольный SQL из архивного файла.

Полная производственная копия получена после входа владельца 06.10.2026 и восстановлена: `.sites-runtime/backups/production-2026-10-06/full.json`, хеш и результаты в журнале требований. Перенос и откат прошли на отдельной копии; исходный архив неизменён. Архив JSON дополняйте исходниками соответствующей сохранённой версии Sites: базовые учебные материалы находятся в коде, редакторские правки — в БД.

## Перенос истории и откат

Миграция `0004_harsh_leech.sql` только добавляет `learner_event_versions` и индексы. Sites применяет её перед Worker; локально — `npm run db:migrate`. История переносится при следующем сохранении или администратором: панель редактора → «Обслуживание истории» → проверка формата → перенос каждого профиля. Это не меняет ответы, освоение, профиль или согласия.

Перед выпуском на НОВОЙ копии архива выполните:

```powershell
node --experimental-strip-types scripts/check-event-migration.mjs C:/secure-backups/ent-math.json C:/secure-backups/migration-rehearsal.sqlite
```

Скрипт отказывается перезаписывать существующий файл; сравнивает весь профиль и хеш истории, проверяет безопасный повтор, добавляет явно тестовый ответ только в копию и доказывает, что обратный перенос его сохраняет. После выпуска скачайте новый v2 архив, восстановите в новый SQLite и сравните исходные данные. Не используйте старый снимок для отката с потерей новых ответов.

Откат к коду версии 9 требует возврата формата данных:

1. Сохраните независимый полный архив актуальных данных.
2. Установите серверную переменную `EVENT_STORAGE_MODE=legacy` и разверните **код с поддержкой событий**. Чтение событий продолжает работать, новые записи снова сохраняются развёрнутым снимком.
3. В обслуживании истории верните все профили в прежний формат; endpoint защищён правами администратора и CAS. При 409 повторите проверку версии, не подставляйте вымышленную. Убедитесь, что список больше не содержит формата событий.
4. Скачайте и восстановите архив с результатом обратного переноса, сравните данные. Только теперь можно развернуть код 9. Таблицу событий не удаляйте: она нужна для чтения старых резервных снимков, если вновь включить новый код.

Версия 9: `appgprj_6ac3df9ebfc08191aa0d491c33887a65~appgver_ed8277320930819183d788b82cb4c300`, commit `44f03289fc966a9dc34b3132f16374839159489e`. Прямой откат к ней **до обратного переноса запрещён**: она не умеет собирать историю из новой таблицы. Производственный откат под живой нагрузкой ещё не испытан.

По умолчанию `EVENT_STORAGE_MODE=events`. Сохранение агрегата, изменений истории, награды и резервного снимка выполняется в одной D1 batch-транзакции с контролем ревизии и токена; неудачный CAS не оставляет событий. Старые ветви событий сохраняются для резервных снимков. Разовая слишком большая миграция останавливается с 507 без записи; нужна отдельная пакетная утилита. Сейчас сервер читает полную историю для совместимости учебного движка, поэтому 10 000 записей в тесте не являются доказательством неограниченной масштабируемости. Границы D1 проверены по [batch API](https://developers.cloudflare.com/d1/worker-api/d1-database/) и [лимитам D1](https://developers.cloudflare.com/d1/platform/limits/).

## История и аналитика

`GET /api/history?kind=attempts|exams&before=<id>` возвращает до 40 более ранних записей авторизованного ученика; неизвестный курсор — 409. ## Выпуск экзаменационного банка

`lib/exam-reserve-data.json` — серверный резерв, его нельзя импортировать в компоненты с `use client` или выдавать учебным API. Версия `exam-2026.1` содержит 10+10 вариантов. `lib/exam-reservations.ts` исключает использованные условия из новых генераций практики. Старые задания и результаты не удаляются; совпадения помечаются знакомыми.

Сборщик `node --experimental-strip-types scripts/build-exam-reserve.mjs` запускают только при целенаправленном новом выпуске после предметной проверки. Он не вызывается при запросе ученика. При изменениях нужно назначить новую версию и перепроверить хеш, независимость условий, квоты, ключи и содержательную сложность. Тесты: `tests/exam-reserve.test.ts`, `tests/exam-rules.test.ts`, `tests/http-exam-reserve.test.mjs`.

В `lib/exam-rules.ts` хранится отдельная версия оценивания. Новый официальный порядок требует нового ID и отдельного обработчика; нельзя менять таблицу под прежним ID. Старые незавершённые экзамены завершаются по своим правилам, законченные результаты повторно не оцениваются. Неизвестная конфигурация останавливает завершение без записи: восстановите совместимый обработчик из предыдущего проверенного выпуска. Перед откатом сохраняйте актуальный полный архив; прежние локальные копии не заменяют новые результаты.


## Обращения и добавочная миграция 0005

`help_tickets` хранит категории, статусы, неизменяемый снимок материала, ответы редактора и номер ревизии. `/api/help` выдаёт только свои обращения; очередь `?queue=editor` и ответы проверяют администратора на сервере. Оператор отвечает из панели редактора; внешняя почта не отправляется. Не обещайте срок ответа, пока владелец не назначит ответственного.

Старые сообщения остаются в прежней таблице; при первом ответе редактора создаётся обращение с тем же ID. На первом экране отдельно показываются до 40 прежних сообщений; новый список имеет пагинацию по 40. Для больших исторических архивов потребуется отдельный перенос всех сообщений.
