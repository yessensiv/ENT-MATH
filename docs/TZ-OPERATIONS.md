## Реальный ИИ — требуется настройка владельца

1. Выберите провайдера с OpenAI-совместимым API, модель, дневной и месячный денежный лимит. Решение о бюджете пока не получено. Для OpenAI подключите плагин **OpenAI Developers**, чтобы настроить ключ через предусмотренный им безопасный процесс; не присылайте ключ в чат.
2. В секретах окружения Sites установите `TUTOR_API_KEY`. Обычные серверные переменные: `TUTOR_BASE_URL`, `TUTOR_MODEL`, `TUTOR_VISION_MODEL`, `TUTOR_DAILY_LIMIT`, `TUTOR_DAILY_TOKEN_LIMIT`. Имена и пример — `.env.example`. Не используйте `NEXT_PUBLIC_` и не записывайте ключ в Git.
3. Локально те же значения можно положить в игнорируемый `.dev.vars`; для production настройте переменные самого проекта Sites и разверните сохранённую версию. Локальный файл не подключает облако.
4. У провайдера установите ограничение расходов. Приложение ограничивает запросы и резервирует токены на ученика; общего денежного счётчика ещё нет. Серверная запись сохраняет фактические токены, если провайдер их вернул, но это ещё не расчёт стоимости.
5. После подключения проверьте маленькую подсказку, ошибочный шаг, альтернативное решение, полный разбор по запросу, новую задачу и отказ провайдера на RU/KK. Экспертный набор 200 случаев — отдельная незавершённая приёмка.

Сейчас UI честно показывает «Учебный помощник • без генеративного ИИ». Его ответы и история работают без ключа.

## Google — выбран, пока не реализован

Владелец выбрал Google как самостоятельный вход без обязательного ChatGPT. Кнопка Google на странице авторизации **ChatGPT** этого требования не выполняет.

Платформа Sites владеет текущими маршрутами входа и заголовками идентичности. Прежде чем добавлять стороннюю авторизацию, нужно подтвердить поддерживаемую интеграцию внешнего провайдера у Sites; такое подтверждение пока не получено. Нельзя подменять `/signin-with-chatgpt`, `/signout-with-chatgpt`, `/callback` или доверять переданному браузером email.

После подтверждения механизма потребуются:

- Google Cloud OAuth Web client, client ID и client secret в серверных секретах, consent screen, страницы политики конфиденциальности и условий.
- Контролируемый домен и подтверждённый HTTPS callback. Предлагаемый **будущий**, пока не работающий путь — `/api/auth/google/callback`; не активируйте интеграцию до реализации и проверки этого обработчика. Системный браузер нужен для входа Google.
- `openid email profile`; идентификация по Google `sub`. Совпадение email не связывает профили и не выдаёт администратора. Привязка выполняется только из уже авторизованного действующего профиля с отдельным подтверждением.
- Проверка `state`, PKCE, nonce, iss/aud/exp; защищённые серверные сессии и отзыв; два реальных аккаунта и тест сохранения истории после привязки.

Первичные источники: [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect), [Web-server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [политики OAuth](https://developers.google.com/identity/protocols/oauth2/policies). Код собственного Google OAuth и сессий пока не выдан за готовую интеграцию.

## Полная резервная копия и проверка

1. Войдите в опубликованный сайт реальным аккаунтом владельца из `ADMIN_EMAILS`. Откройте панель редактора → «Скачать полную резервную копию». `/api/admin/backup` доступен только администратору. Сохраняются 12 таблиц с контрольной суммой. Более 10 000 строк в одной таблице или 24 МБ требует отдельного полного экспорта D1; усечённая копия не считается полной.
2. Положите файл в защищённое хранилище **вне** основной базы/деплоя. В нём профили, решения, переписка и согласия: не публикуйте его в репозитории или общедоступной ссылкой. Настройте права, шифрование и политику 30 дневных/12 месячных копий после согласования бюджета и сроков хранения.
3. Из корня проекта проверьте и восстановите в **новый** файл:

```powershell
node --experimental-strip-types scripts/verify-backup.mjs C:/secure-backups/ent-math.json
node --experimental-strip-types scripts/restore-backup.mjs C:/secure-backups/ent-math.json C:/secure-backups/restore-check.sqlite
```

Вторая команда откажется перезаписывать существующий файл. Она применяет схему из доверенного репозитория, сверяет таблицы, строки, контрольные суммы состояния и `integrity_check`. Для повторного испытания задайте другое новое имя. Указанный каталог — пример: сначала выберите собственное защищённое место.

4. Сверьте профиль, экзамен, учебную историю и публикации в изолированной тестовой среде. Затем отдельно подготовьте импорт в новую D1 и переключение привязки Sites; автоматического импорта этого JSON в production в выпуске нет. Не запускайте произвольный SQL из архивного файла.

Локальная проверка восстановления прошла. Production-выгрузка через штатный инструмент просмотра таблиц была усечена и непригодна как резерв; после добавления полного экспорта нужен вход владельца. До этого производственная миграция схемы и перенос событий остановлены. Новое обновление использует прежние таблицы и добавляет поля без удаления старых.
